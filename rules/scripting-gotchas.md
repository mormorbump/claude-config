# シェルスクリプト・AWS CLI・CI のハマりどころ

## シェル
- `set -o pipefail` の下で `cmd | grep -q x` と書かない。grep が一致で早く抜けると左側が SIGPIPE で死に、一致したのにパイプライン全体が失敗になる
- 関数内のコマンド置換 `$(...)` には `set -e` が効かない。API やコマンドのエラーを「無い」「0 件」と読むコードを書かず、終了コードを明示的に見る

## AWS CLI
- AWS CLI は時刻をローカルのタイムゾーンで返す。時刻を比べるスクリプトは `TZ=UTC` に固定する
- `aws login` のセッションは約 12 時間で切れ、切れると後始末を含む全 API が失敗する。長い検証や破棄の前にユーザーにログインし直してもらう
- `aws logout --profile X` は、同じ `login_session` を指す別プロファイルのログインも消す（キャッシュがセッション単位）
- 既存スタックに `aws cloudformation deploy` を `--tags` なしで掛けると、全リソースからタグが外れる差分になる（NAT Gateway の置き換えが出ることもある）。既存と同じ `--tags` を必ず渡し、単独更新は変更セットで差分を確かめる

## GitHub Actions
- job レベルの `if: hashFiles(...)` は checkout 前に評価されるので常に空を返す。ファイル存在の判定は checkout 後の step でシェルで行う
- ワークフローは実行して初めて挙動が分かる。YAML parse や `bash -n` などの静的検査で済ませず、使い捨てリポジトリへ push して実行を確かめるか、未検証であることを報告に明記する
